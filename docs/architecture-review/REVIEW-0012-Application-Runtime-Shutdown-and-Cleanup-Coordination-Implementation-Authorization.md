# Proposed Behavior

## Shutdown request and state correspondence

Add only the internal `shutdown(): Promise<void>` operation. On the first request, close admission synchronously before returning the Promise. This closes new preparation and new turn admission permanently. It does not expose a public Runtime package API or transport surface.

The complete state model is Not Prepared, Preparing, Ready, Preparation Failed, Turn In Progress, Admission Closed, Cleanup In Progress, and Terminal Closed. Closure state and outstanding admitted-operation bookkeeping must coexist. Do not import Knowledge-specific state names or add a cleanup-failed/shutdown-failed Runtime state.

| State when shutdown is requested        | Required behavior                                                                                                                                                  |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Not Prepared                            | Close admission and invoke retained cleanup with no preparation requirement.                                                                                       |
| Preparing                               | Close admission; let the one Context preparation and corresponding Brain binding operation settle; preserve its outcome and closed admission, then invoke cleanup. |
| Ready                                   | Close admission and invoke cleanup; no new turn may enter.                                                                                                         |
| Preparation Failed                      | Close admission and invoke cleanup; no retry or re-preparation.                                                                                                    |
| Turn In Progress, execution not started | Close new admission, preserve the unconsumed admission, and wait for its one explicit execution and settlement.                                                    |
| Turn In Progress, executing             | Close admission, allow the synchronous invocation to finish without interruption, preserve its outcome, and invoke cleanup after settlement.                       |
| Admission Closed                        | Join the existing logical shutdown completion; continue waiting for admitted work if outstanding.                                                                  |
| Cleanup In Progress                     | Join existing completion; do not invoke another cleanup.                                                                                                           |
| Terminal Closed                         | Observe the completed success or failure; never reopen admission or retry cleanup.                                                                                 |

With no outstanding admitted work, Admission Closed may progress immediately to Cleanup In Progress within the first shutdown call. No artificial delay is required to make Admission Closed persist. Cleanup In Progress must be observable while cleanup is pending. Terminal Closed must precede observable shutdown completion.

## Preserved preparation and turn settlement

Preserve the single-preparation-attempt invariant and the existing Context/Brain binding sequence. Shutdown during either Context preparation or binding permits that same synchronous operation to settle without cancellation, replacement, retry, skipped binding on an otherwise successful preparation, or a second preparation. Its settlement must not overwrite closure with Ready or Preparation Failed. A failure retains its originating value/ownership.

An admission obtained before closure remains executable exactly once even if execution has not started. Consuming it through `executeTurn(request)` is not new admission. Reject new admission and overlapping/reentrant execution immediately. Shutdown remains pending until this admitted turn is explicitly executed and settles. If it is never executed, Runtime remains Admission Closed and shutdown remains pending indefinitely. No finite deadline is promised; no timeout, discard, cancellation, request inference, fabricated result/failure, or autonomous execution is permitted.

For an executing or preserved turn, accept one existing caller-supplied `NormalizedCognitiveRequest`, forward the exact object unchanged to the retained Brain binding, invoke synchronous `orchestrateCognitiveRequest` exactly once, and return the exact Brain-issued `FinalCognitiveResult` or surface the exact originating thrown value. No transformation, wrapping, normalization, persistence, interpretation, or feedback is introduced. Before closure, preserve REVIEW-0011's Turn In Progress state throughout invocation; after shutdown begins, preserve closed admission and outstanding-work bookkeeping rather than reverting to Turn In Progress or Ready. Closure must remain effective before result/failure observation.

`begin`, `executeTurn`, and Brain orchestration remain synchronous. Shutdown requested reentrantly during preparation, binding, or execution must return its Promise without synchronously blocking the stack that must settle the admitted operation. The existing asynchronous composition factory does not justify asynchronous cognitive execution.

## Delegated cleanup and terminal outcomes

Invoke only the already-retained C1 composition's existing `shutdown()` after any admitted operation has settled. Preserve one logical delegated cleanup execution. Enter Cleanup In Progress when delegation begins. Runtime must not call Engine stop methods, dispose resources directly, reproduce Knowledge recovery/queue policy, or claim global revocation of retained Context/Brain handles.

On cleanup success, enter Terminal Closed before fulfilling shutdown with `undefined`. On cleanup failure, enter Terminal Closed before rejecting shutdown with the originating cleanup failure. Failure remains observable, admission remains permanently closed, and there is no retry. Terminal Closed means permanent Runtime closure and a settled shutdown outcome; it does not assert successful resource disposal or a successful underlying Engine stopped state.

Preserve one logical shutdown completion across requests while admitted work is pending, during cleanup, after success, and after failure. Repeated requests join or observe that completion; no second cleanup occurs. Later calls after success fulfill without further cleanup; later calls after failure reject with the existing failure rather than becoming successful no-ops. Exact Promise object identity is not required and must not be promoted into a normative conformance requirement. Ignoring/dropping a shutdown Promise does not cancel work or cleanup.

Keep admitted-operation and cleanup outcomes separate. Cleanup failure must not replace or mask an operation's result or originating failure. An ordinary preparation/turn failure alone must not reject shutdown if cleanup subsequently succeeds. Any synchronous failure encountered while invoking the existing cleanup boundary must likewise be delivered through shutdown completion rather than escape through the admitted operation's settlement path; this preserves the approved outcome channels and introduces no new failure taxonomy or Engine repair.

After closure, reject every new preparation and new turn admission. Execution without the one preserved unconsumed admission remains invalid; after its consumption or terminal closure no further turn may execute. Only repeated shutdown observation remains permitted among these lifecycle operations.

## Regression and ownership constraints

Without shutdown, preserve REVIEW-0008 through REVIEW-0011 behavior: one composition per instance, one explicit preparation attempt, exact preparation/binding correspondence, Ready-only admission, immediate overlapping-operation rejection, exact request/result/failure propagation, ordinary success/failure settlement back to Ready before observation, and fresh explicit admission for later turns. Active 2.0.1 changes only the specified closure-aware cases.

Retain instance independence and existing privacy/authority boundaries. Runtime gains no result retention, conversation memory, source authority, Context/Brain semantic ownership, resource disposal authority, or production capability. Do not use this slice to refactor unrelated behavior or fix another service.

Mandatory successful-preparation/failed-cleanup evidence: request shutdown reentrantly during successful Context preparation and, separately, during successful Brain binding. For each shutdown-request location, cover both (A) delegated cleanup returning a Promise that rejects with the originating cleanup failure and (B) the delegated cleanup invocation throwing synchronously before returning a Promise. In every case, assert all of the following:

1. `begin()` returns normally and synchronously; successful preparation is not converted into, replaced by, or surfaced as preparation failure.
2. Context preparation completes exactly once and Brain binding completes exactly once.
3. Closure remains effective and is never overwritten by Ready or Preparation Failed.
4. Cleanup is invoked only after the admitted preparation/binding operation has settled; Runtime is Cleanup In Progress when delegation begins.
5. Runtime reaches Terminal Closed before the originating cleanup failure is observable through shutdown. Only shutdown rejects with that exact failure; cleanup failure does not escape through `begin()` or retroactively alter its already-completed successful outcome.
6. Cleanup is not retried. Repeated shutdown observes the same logical failed outcome and originating failure, with one delegated cleanup execution; exact Promise object identity is not required.

This mandatory evidence covers successful preparation plus failed cleanup for both failure forms without changing the approved behavior, cleanup ownership, or implementation boundary.
